## Agent 与工作流

Agent（智能体）是当前 AI 产品的核心范式：**从"回答你的问题"到"帮你把事情做完"**。

## 什么是 Agent

Agent = LLM + 工具 + 循环决策。与普通对话相比，Agent 能：

-   **调用工具**：搜索、读文件、操作软件、调 API
-   **自主规划**：把大任务拆成子任务，决定执行顺序
-   **感知结果**：执行一步后看结果，再决定下一步
-   **循环执行**：直到任务完成或达到终止条件

## 常见架构

| 架构 | 说明 | 适用场景 |
| --- | --- | --- |
| 单 Agent | 一个模型 + 一组工具 | 任务边界清晰 |
| 工作流 (Workflow) | 预先编排好的步骤，每步调模型/工具 | 流程固定、要稳定 |
| 多 Agent 协作 | 多个 Agent 分工（如 写手+审稿+排版） | 复杂任务、质量要求高 |
| 人机协同 | Agent 执行 + 关键节点人工确认 | 风险高、结果不可逆 |

## 产品设计要点

-   **任务边界**：明确 Agent 能自主到什么程度——权限最小化
-   **进度可见**：展示"正在做什么、用了什么工具"，建立信任
-   **确认节点**：花钱、发消息、删数据等不可逆操作必须人工确认
-   **失败兜底**：Agent 会卡住、会走弯路，要设置最大步数、超时、人工接管
-   **成本控制**：多轮循环 token 消耗大，需要预算上限

## 与 RAG 的关系

Agent 经常包含检索能力（Agentic RAG），但 Agent 更进一步——它能**决定**要不要检索、检索什么、怎么利用结果，而非固定地"先检索再生成"。

## 当前边界（务实的预期管理）

-   复杂长程任务成功率仍有限，商用场景普遍是"工作流 + 人工复核"
-   多 Agent 协作的成本与不稳定可能超过收益，先用单 Agent + 工具

???+ example "练习"
    选一个你熟悉的重复性工作（如"汇总周报并生成摘要"），设计：它需要哪些工具、哪些步骤、哪些节点需要人工确认。
