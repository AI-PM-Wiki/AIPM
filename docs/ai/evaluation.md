## 评估与评测

"这个 AI 产品到底行不行？"——**没有评估，就没有迭代**。评估是 AI 产品经理最重要的基本功之一。

## 为什么评估难

-   模型输出是**概率性的**：同样输入，两次结果可能不同
-   质量是**多维度的**：准确、流畅、相关、安全、风格……很难一个分数说清
-   人工评测贵，自动评测不准

## 三层评估体系

### 1. 评测集（离线）

-   收集**代表性输入**：典型场景、边界场景、对抗场景
-   为每个输入标注**期望行为**（答案要点、禁止行为）
-   每次改模型/提示词后跑一遍，作为回归防线

### 2. 线上指标（在线）

| 指标 | 说明 |
| --- | --- |
| 任务完成率 | 用户请求最终是否达成 |
| 采纳率 | 生成结果被用户采用/修改的比例 |
| 错误率/投诉率 | 用户明确表示不满 |
| 重试率 | 用户是否反复追问同一问题 |
| 会话深度 | 多轮对话的比例与长度 |

### 3. 用户体验（定性）

-   用户访谈、可用性测试
-   把真实对话记录抽样复盘（注意脱敏）

## 常见评测维度

-   **准确率**：事实正确性
-   **忠实度**：是否忠于给定资料（RAG 场景）
-   **相关性**：回答是否切题
-   **完整性**：是否漏掉关键点
-   **安全性**：是否输出有害内容
-   **风格**：是否符合品牌与场景

## 实操建议

-   **种子评测集从第一天建**：20 条就够了，边做边扩充
-   **失败案例库**：每次上线后收集用户不满意案例，回填评测集
-   **人工抽检常态化**：每周抽 20-50 条真实对话人工评分
-   **版本对照**：新模型/新提示词上线前，同一评测集新旧对照

### 评测会失效：持续校准（CC）

评测集基于"预期用户行为"设计，而 AI 用户的真实行为是非确定的——**评测失效、需要重做，完全正常**，通常要跑多轮。CC（持续校准）阶段的做法：运行评测 → 人工审查最弱环节（每部门抽 20~50 条低分样本）→ 归纳错误模式（表格：模式/触发条件/影响/修复方向）→ 数据驱动修复。

完整的 CC/CD 生命周期见 [AI 产品开发生命周期（CC/CD）](../pm/ai-lifecycle.md)。
