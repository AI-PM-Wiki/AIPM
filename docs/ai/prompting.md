## 提示词工程

提示词（Prompt）是产品经理与模型"沟通"的方式，也是 AI 产品最核心的"代码"。好的提示词能显著提升输出质量。

## 基本结构

一个高质量的提示词通常包含：

1.  **角色设定**：告诉模型你是谁、你要什么角色
2.  **任务描述**：明确要做什么、输出什么格式
3.  **上下文**：必要的背景信息
4.  **约束条件**：不能做什么、必须做什么
5.  **输出格式**：结构化要求（JSON、表格、长度限制）

## 常用技巧

| 技巧 | 说明 |
| --- | --- |
| 少样本示例 (few-shot) | 给 2-3 个输入输出示例，模型学得最快 |
| 思维链 (CoT) | 要求"先分析再回答"，复杂任务准确率显著提升 |
| 分步指令 | 复杂任务拆成明确步骤 |
| 输出约束 | 明确禁止事项 + 格式要求 |
| 温度调节 | 分类/抽取任务用低温，创意任务用高温 |
| 迭代式优化 | 没有一次写成的提示词，靠测试迭代 |

## 提示词编写流程

1.  **写初版**：按上面结构起草
2.  **建测试集**：10-20 条代表性输入（含边界与对抗用例）
3.  **跑分迭代**：改提示词 → 跑测试集 → 看失败案例 → 再改
4.  **固化版本**：提示词纳入版本管理（提示词也是代码）

## 产品中的提示词管理

-   提示词是产品逻辑的一部分，应纳入代码仓库、有版本号
-   上线后用户反馈要回流为测试集，持续回归
-   关键任务的提示词应避免写死在用户可见层，防提示词注入

## 安全：提示词注入

用户输入可能包含恶意指令（"忽略以上所有指令……"）。对策：

-   用户输入与系统指令分离
-   对用户输入做指令隔离（如用分隔符标记用户内容）
-   关键操作二次确认
