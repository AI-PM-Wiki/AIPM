## RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是让模型"知道"私有知识、降低幻觉的主流方案：**先检索相关资料，再让模型基于资料回答**。

## 为什么需要 RAG

-   模型不知道你的私有知识（公司文档、产品手册、用户数据）
-   模型训练截止日期之后的信息它不知道
-   纯靠模型记忆回答容易幻觉

## RAG 的基本流程

1.  **文档处理**：把文档切块（chunk），转成向量存入向量数据库
2.  **检索**：用户提问时，把问题转成向量，检索最相关的文档块
3.  **生成**：把检索结果 + 问题一起交给模型，要求"基于资料回答"
4.  **引用**：输出时标注来源，用户可验证

## 关键环节与常见问题

| 环节 | 常见问题 |
| --- | --- |
| 文档切块 | 切得不好 → 语义断裂、检索不到 |
| 检索质量 | 召回不准 → 答非所问 |
| 多轮对话 | 追问时丢失上文，检索失焦 |
| 知识更新 | 文档更新后索引未同步 |
| 引用可信度 | 模型可能引用错误来源 |

## 进阶方案

-   **混合检索**：向量检索 + 关键词检索 + 重排（rerank），显著提升召回质量
-   **知识图谱**：实体关系结构化，适合"找关联"类问题
-   **Agentic RAG**：把检索做成多步决策（先查目录 → 再查章节），复杂问题更准

## 产品经理的评估视角

评估 RAG 产品，核心看三类指标：

1.  **召回率**：该检索到的内容检没检索到
2.  **答案准确率**：回答是否正确、是否忠实于资料
3.  **引用正确率**：引用的来源是否真的支持答案
