## 理想态

任何产品都是用来解决用户问题的。产品的理想态，就是给出的方案确实解决了用户的问题。自然语言可以先写成：搜索找到需要的信息、出行到达目的地、内容产品找到想看的内容、天气产品拿到准确信息。这些描述还不够：下一步必须找到可衡量的数字化指标或明确标准。

理想态是[阶段性调研](05-periodic-research.md)的起点。第二步要找出「未达到理想态」的 Case。如果理想态没先定义，团队无法统一判断什么算满足、哪些问题进清单、哪个更严重、上线后用什么标准做[效果回归](../03-spec-and-validation/05-effect-review.md)。它的作用是提供当前阶段可执行的比较基准。这也是[策略通用方法论](../03-spec-and-validation/06-methodology.md)「定义理想态 → 拆未达情况 → 提方案 → 验证」的第一环。

先从用户任务出发。用一句话回答：用户在什么场景下，想通过产品完成什么任务？不要把「看到列表」「点击按钮」「获得曝光」直接当成理想态。那是产品动作，不一定是用户价值。再写成可判断命题：当 ______ 发生时，我们认为用户在当前阶段达到理想态。

「简单 / 复杂」说的是满足效果的可衡量性，不是页面复杂度、技术难度或公司规模。

### 简单理想态：单一指标可近似衡量

工具类、刚需类产品，或一个产品中的独立策略模块，往往可以用「解决问题 + 单一指标」定义。课程把出行成交和天气准确率归为这一类：用户问题是否解决，较容易找到一个单一指标近似衡量。

-   若目标是把乘客送到目的地，可用订单成交率衡量。
-   若目标是提供准确天气，可用天气信息准确率衡量。

口径必须写清分母、完成定义和统计时间，否则不同团队会用不同数字争论结果。下列公式是教学示意：

```text
达成理想态率 = 达成理想态的用户或订单数 ÷ 进入该任务的用户或订单总数
```

### 复杂理想态：点击不等于满足

搜索和推荐属于复杂情况：用户满足很难被单一行为直接观察。

-   **点击不等于满足**：用户可能点了很多条，却一直没找到有用信息。
-   **不点击也不等于不满足**：用户可能在结果页直接看到了天气、时间、地点，不需要再点。
-   **停留时长也不是天然目标**：内容里停五分钟、一小时还是更久，不能凭空规定一个「理想值」。长停留可能是投入，也可能是内容不清、反复寻找。

因此，复杂产品的理想态要从「用户真实需求不可完全观测」出发，用平台当前能够给出的最佳解决方案作为阶段性理想态。对搜索和推荐，可以把「最佳可行方案」拆成：识别用户可能的需求；评估候选是否相关；给出当前平台能做到的最佳结果集合；让排序、形式和覆盖符合当前阶段目标；用代表性行为和人工判断持续修正。这里的「最佳」是阶段性、可实现的最佳。

复杂理想态不强行压成一个数字，而是一组判断维度：

```text
阶段性满足判断 = 需求识别 + 结果相关性 + 覆盖与排序 + 行为证据 + 人工评估
```

这不是固定加权公式，调研时必须写清每一维如何判断。推荐比搜索更难：用户和平台都未必知道下一刻想看什么，不能把每条推荐的点击率设成百分之百。点击率等行为数据用来找重点 Case，不能单独定义全部满足效果。延伸见[搜索策略](../05-function-oriented/02-search.md)。

### 搜索：从「每个词」走向「每次搜索」

同一个搜索词可能对应许多需求。课程用「苹果」举例：用户可能在找公司官网、手机评测、电影、水果营养或农产品价格。因此不能简单说「点击率高就是满足」。应结合：上下文搜索（用户此前搜过什么）、点击行为、改词行为、用户画像，以及竞品与人工评估。

早期产品可能只能定义为「在每个搜索词下给出通用最佳结果」：一万人搜同一个词，看到同一套静态结果。随着移动端行为数据更完整，理想态可以进化为「满足每个人的每一次搜索」：一万次搜索可能因用户和上下文不同，得到一万种结果。这是两个不同阶段的理想态，不要混用。

### 阶段性理想态会进化

理想态不是永久不变的 KPI，必须服务于当前阶段的产品目标，并跟着产品能力、数据和用户理解能力提升而进化。反例是把「瞬间移动」当成打车的当前理想态：更理想，但对当前工作没有操作意义。

课程用出行说明能力扩张后的变化：

1.  **早期**：平台只负责连接用户和司机，可用司机应答率衡量阶段目标。
2.  **能力扩大**：覆盖更多运力和线上支付后，指标可扩展到订单成交率，即完成完整出行闭环。
3.  **再进化**：开始追求更快、更有预期的到达时间。

同理，搜索早期更关注一个 query 下的通用最佳排序；有了更完整的用户行为后，可以更关注每个用户每次搜索的个性化满足。不能一开始就把平台尚未覆盖的环节纳入考核，也不能能力已经扩展后仍停留在过窄指标。出行匹配的后续展开见[出行匹配策略](../06-business-oriented/03-ride-matching.md)。

### 判断简单还是复杂

| 判断问题 | 偏简单 | 偏复杂 |
| --- | --- | --- |
| 用户目标是否单一、明确？ | 是 | 否 |
| 结果完成是否能直接观察？ | 交易完成、信息准确 | 需要上下文或人工判断 |
| 单一行为能否可靠代表满足？ | 可作为核心指标 | 不能直接等同 |
| 产品是否在猜测非刚性需求？ | 否 | 搜索 / 推荐式定义 |

写理想态时盯住三件事：这一句话能否指导抽样和标注；核心指标或证据组合能否被团队复述；「本阶段不纳入」有没有把终极愿景误写成当前 KPI。

四步找理想态：

1.  从用户任务而不是页面功能开始。
2.  写出可观察的完成标准。
3.  判断属于简单还是复杂。
4.  复杂产品用「最佳可行方案」定义，并列出辅助证据。

如果理想态写完后，[抽样分析](06-sampling.md)仍然不知道该抽用户、Session、query 还是订单，说明完成标准还不够可操作。如果上线后效果回归只能看一个与理想态无关的虚荣指标，说明当时把产品动作当成了用户价值。

一句话自检：在当前阶段，用户完成什么任务算被解决？我们用什么可观察标准判断？哪些行为明确不能等同于满足？下一次产品能力变化时，这张定义卡什么时候必须重写？说不清任何一句，理想态就还停留在口号。

### 理想态定义卡

| 项目 | 填写内容 |
| --- | --- |
| 产品 / 模块 | |
| 当前阶段目标 | |
| 用户任务 | |
| 理想态一句话 | |
| 核心指标或标准 | |
| 指标口径 / 分母 | |
| 不能直接等同满足的行为 | |
| 辅助判断证据 | |
| 本阶段不纳入的终极目标 | |
| 下次复审条件 | |

调研开始前的范围卡：

```text
调研对象：
阶段目标：
理想态描述：
核心指标 / 标准：
指标统计口径：
时间范围：
需要重点观察的用户或业务类型：
```

两张卡一起用：定义卡保证「满足」有共同语言，范围卡保证后面抽样不会整体返工。复杂产品还要在定义卡的「辅助判断证据」里写清：上下文、点击、改词、画像、竞品、人工评估各回答什么，避免最后又退化成只看点击率。

简单产品尽量把理想态收成一个核心比率，并在定义卡里写死分母。例如成交率的分母是「用户发出的订单」还是「系统成功创建的订单」，取消、超时、测试单是否计入，都必须在调研开始前写完。否则抽样总体都会漂。

复杂产品不要假装有一个「满足率字段」可以自动筛 Case。先写满足判定规则，再抽样。可把课程中的起始判断整理成下表，作为标注手册草稿：

| 用户行为 | 结果检查 | 阶段性判断 |
| --- | --- | --- |
| 无点击、无改词、无翻页、无切换 | 结果中已有清晰且正确的答案 | 满足 |
| 只点击一条、之后无其他行为 | query 与该结果高度匹配，足以完成任务 | 满足 |
| 点击多条后才找到可用结果 | 结果存在，但获取成本偏高 | 满足不够好 |
| 多次点击、改词、翻页或切换后仍无结果 | 无法完成需求 | 不满足 |
| 改写 query 后才找到答案 | 原 query 解析或扩展可能有问题 | 原次搜索不满足或满足不够好 |

「满足成本」可以先用离散等级：低（结果页直接得到答案，或只需一次有效点击）、中（多次点击、返回或翻页）、高（改词、切换产品线或重复搜索）、无法完成。不要在没有课程给定公式时伪造精确数值。

能力扩张后，通常改的是「本阶段纳入的环节」和「核心指标」，不改的是「用户任务」这一句。出行用户的任务始终是到达目的地；变的是平台能不能考核应答、成交还是准时。搜索用户的任务始终是找到信息；变的是按每个词给通用最佳，还是按每次搜索给个性化最佳。下次复审条件可以写成：平台开始掌握支付 / 运力 / 个性化特征时，重开定义卡。

### 误区与边界

-   **把点击率当成满足率。** 点击可能是找不到答案后的反复尝试；不点击也可能是结果已在页内解决问题。
-   **把停留时长越长越好。** 长停留可能是投入，也可能是内容不清、反复寻找或无效消耗。
-   **把理想态写成永久目标或口号。** 「提升体验」「让用户满意」不能指导抽样和标注，必须转成指标或明确标准。
-   **用页面或技术复杂度给产品分类。** 简单 / 复杂指满足效果是否容易衡量。
-   **忽略平台边界。** 早期出行产品不能用平台尚未掌控的全流程结果作为唯一目标；能力扩大后又需要及时扩展指标。
-   **混淆静态 query 最优与单次个性化最优。** 「每个词」和「每次搜索」是两个阶段。
-   **把简单产品的单一指标直接套到搜索 / 推荐。** 复杂产品要承认意图不可完全观测。

对目标清晰、闭环明确的交易 / 工具产品，优先寻找单一核心指标。对隐含需求多、意图不可完全观察的搜索 / 推荐，使用阶段性最佳方案 + 多维证据。复杂理想态不能替代后续抽样和人工标注，它只是为抽样定义「要找什么」。必须结合控制边界、用户任务和当前阶段重写口径。理想态会进化，因此要写「下次复审条件」。课程中的成交率、天气准确率、「苹果」多意图只是找理想态的例子，不是可直接迁移的业务事实。

定义卡写完后，最好立刻用两个真实 Case 试标：一个你认为已满足，一个你认为未满足。如果两个人标不一致，先改定义卡，再开始大规模抽样。试标的两个人最好一个偏业务、一个偏策略或标注。意见一致，定义卡才能当团队尺子；意见不一致，先改「不能直接等同满足的行为」这一栏。

定义卡建议和调研范围卡一起存进同一份笔记，并在阶段目标变化时整张重写。理想态是比较基准，基准一漂，抽样、优先级和回归会一起漂。
