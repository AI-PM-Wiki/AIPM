## Agent 产品

Agent 产品让 AI 不只是"回答"，而是**独立完成任务**：写报告、做调研、管日程、自动化运维。技术背景见 [Agent 与工作流](../ai/agent.md)。

## 产品形态

| 形态 | 自主程度 | 例子 |
| --- | --- | --- |
| 任务型 Agent | 完成单个明确任务 | 一键生成周报、调研报告 |
| 流程型 Agent | 完成多步固定流程 | 报销流程、简历筛选 |
| 陪伴型 Agent | 持续运行、主动行动 | 智能助理、监控机器人 |

## 核心设计问题

### 1. 边界与权限（最重要）

-   Agent 能调用什么工具、触碰什么数据——**最小权限原则**
-   不可逆操作（发消息、付款、删除）必须人工确认
-   权限边界是 Agent 产品的信任基石

### 2. 进度与信任

-   展示执行过程：当前步骤、调用了什么工具、依据是什么
-   用户可以中途插入修改、暂停、接管

### 3. 失败处理

-   设置最大步数、超时、成本上限
-   任务失败要有"人工接管"路径，不能静默卡死

### 4. 人机分工

-   "能自主的自主、该确认的确认"——确认节点要设计在**风险点**而非每一步

## 常见坑

-   **Demo 陷阱**：演示场景可控，真实场景千变万化——上线前用真实数据压测
-   Agent 反复尝试同一失败路径，浪费 token
-   工具权限过宽，出现"AI 把公司文件删了"级事故
-   忽略了"结果可验证"：Agent 产出的报告没人核对，比没有更糟

## 架构参考

简单的先上：**固定工作流 + 单 Agent + 人工复核**，跑通后再逐步增加自主度。

### 代理权要赚取，不要授予

每多给系统一分**代理权**，就少一分控制：建议式回复可以覆写，自动发送就必须确保正确。常见错误是系统还没证明"犯错时可控"就直接上全代理——失去可见性、失去信任、动作无法追溯。正确姿势是**控制交接**：出错时人类能无缝接管，如 Agent 做错了一步，用户能一键纠正并记录，信任和可恢复性从这一步开始。

完整框架见 [AI 产品开发生命周期（CC/CD）](../pm/ai-lifecycle.md)。
