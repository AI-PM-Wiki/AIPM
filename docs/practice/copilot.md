## Copilot

Copilot（副驾驶）是嵌入**既有工作流**的 AI 助手：用户继续用熟悉的软件，AI 在旁边提供建议、补全、生成。典型如代码补全、文档辅助、设计辅助。

## 与对话产品的本质区别

| 维度 | 对话产品 | Copilot |
| --- | --- | --- |
| 入口 | 独立聊天窗 | 嵌入既有工具 |
| 上下文 | 用户描述 | **自动感知**用户当前正在做什么 |
| 交互 | 一问一答 | 边做边提示、即点即用 |
| 心智 | "问 AI" | "工具变聪明了" |

## 核心设计问题

### 1. 上下文感知

-   Copilot 的价值来自对用户**当下状态**的理解：光标位置、选中的内容、正在编辑的文件
-   上下文越多越准，但注意隐私边界（什么数据可被感知）

### 2. 打断成本

-   Copilot 的原则是**低打断**：建议要即时、准确、可一键接受/忽略
-   频繁弹无用的建议 = 噪音，用户会关掉它

### 3. 建议的信任

-   建议要短、可预览、可修改
-   高风险建议（自动改写代码、自动回复邮件）需要显示差异并确认

### 4. 采纳率是北极星

-   衡量 Copilot 成败的核心指标：**建议采纳率**
-   采纳率不高时，优先优化"什么时候给建议"，而非"建议的质量"

## 常见坑

-   把 Copilot 做成"嵌在工具栏里的对话框"——失去自动感知就失去灵魂
-   建议出现时机不对（打断心流），引发反感
-   忽略用户已有习惯：Copilot 要适配工作流，不是让用户适配它

???+ example "练习"
    选一款你天天用的软件（如飞书/微信/Excel），设计 3 个 Copilot 能力点，各说明：感知什么上下文、何时给建议、如何显示。
