## 工作流自动化

工作流自动化让 AI 串联多个步骤和工具，把"重复的脑力劳动"变成"一条流水线"：收集 → 整理 → 生成 → 分发。

## 典型场景

-   **内容流水线**：素材收集 → 大纲 → 成稿 → 配图 → 发布
-   **数据流水线**：报表 → 洞察 → 周报生成
-   **运营自动化**：评论收集 → 分类 → 回复建议
-   **个人自动化**：邮件处理、日程整理、消息摘要

## 与 Agent 的区别

-   **工作流**：步骤固定、预先编排，追求**确定性**
-   **Agent**：动态规划、自主决策，追求**灵活性**
-   务实做法：能用工作流解决的别用 Agent

## 设计要点

### 1. 节点设计

每个节点明确：输入、处理（模型/工具/人工）、输出。设计时先画流程图再实现。

### 2. 人工在环

-   关键节点人工确认（发布前、付款前）
-   异常节点转人工（识别失败、置信度过低）

### 3. 可观测性

-   每个节点有日志：哪一步、花了多少 token、结果是什么
-   失败可定位、可重试、可暂停

### 4. 成本

-   每个节点核算成本；高频路径优化（缓存、小模型）

## 常见坑

-   **流程设计先于验证**：想当然画流程，结果单步成功率 90%、五步成功率只剩 59%
-   每步之间没有校验：上游输出坏数据，下游全错
-   忽略了"格式化"节点：AI 生成结果要强制结构化（JSON Schema 校验）
