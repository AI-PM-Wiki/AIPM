## TOC 回归验证

在仓库根目录运行 `bash test/toc/run.sh`。需要 `uv`、Python 3、`ego-browser`，以及已检出且构建过资源的 `mkdocs-material` 子模块。

运行 `bash test/toc/verify-runner.sh` 可分别用临时服务占用 8765、8766 端口，并分别注入默认服务、特性服务的启动失败；四组负向验证都要求测试非零退出。占用场景要求占用者的 PID、响应标记保持不变，且运行器未向其发请求。脚本只停止自身启动的临时服务。

脚本首先检查两个端口未被占用，再从当前源码构建两套页面：默认配置，以及 `features.yml` 中同时启用 `toc.follow`、`navigation.tracking` 的配置。静态预览分别使用本机 8765 和 8766 端口；启动及浏览器结束后均核对各自独有的响应标记和服务 PID，结束时仅停止本次启动的服务。构建输出和服务日志保存在已忽略的 `meta/toc-regression/`。

浏览器在四种视口、六组滚动位置逐项比对 TOC 条目高亮和标题可见性，并检查缩进折线、长标题换行、移动端打开目录时的 8px 尾段。在 `/pm/monetization/` 的 `y=600` 还会分别检验折入、折回两个拐角：水平跨越缩进的位置，在折点上、下各 0.5px 均须处于高亮多边形内部。每组都要求实际检验至少一行；任何目标标题缺失、行数为零或断言失败都会使命令返回非零退出码。功能配置下还会分别在桌面和移动端点击「红队测试」，等待锚点追踪稳定后检查地址栏、标题位置和高亮。
