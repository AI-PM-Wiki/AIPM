## HCM 与人力资源

人力资本管理（HCM）记录组织如何进人、用人、付薪和退出。对象是职位与人。账号在身份目录里，人在 HCM 里；入职开通和离职关闭必须两边同时发生。

劳动与用工红线见 [劳动与合规](../law/practice/labor-and-compliance.md)。薪酬核算会过账到 [ERP 与资源计划](erp.md)。

### 对象

| 术语 | 含义 | 产品经理要写下的规则 |
| --- | --- | --- |
| **组织 / 部门** | 汇报与核算结构 | 与 ERP 成本中心映射；调整组织不自动改历史发薪 |
| **职位 / 岗位** | 编制上的坑位 | 一人一岗或一人多岗要写兼任规则；招聘对着职位而不是对着姓名 |
| **员工** | 劳动合同或劳务关系中的人 | 工号唯一；员工子组决定考勤、发薪与福利方案 |
| **合同与试用** | 用工法律关系 | 到期、续签、终止有日期和文件；模型不生成已签署合同 |
| **考勤 / 假勤** | 出勤与休假余额 | 加班、调休、法定假的日历按地区政策版本化 |
| **薪酬与发薪** | 工资、社保、个税 | 发薪批次有责任人；失败重跑必须幂等 |
| **绩效与目标** | 周期内的目标与评价 | 校准记录可审计；评价人与被评价人权限分离 |

```mermaid
flowchart LR
    req[招聘需求] --> offer[录用]
    offer --> onboard[入职]
    onboard --> work[考勤与绩效]
    work --> pay[发薪]
    pay --> change[调动或晋升]
    change --> offboard[离职]
```

从需求到离职是一条链。任意节点的系统动作都要回到员工主数据，避免 IT 已关账号、HCM 仍在发薪，或相反。

### 制度与流程

-   **招聘**：需求来自编制或批准的增编；候选人评估与录用审批分离；背景调查材料按保留期限管理
-   **入职**：HCM 生效日期驱动身份目录开通、邮箱、权限包、资产领用；提前开通要有失效日
-   **假勤**：余额计算依赖入职日、工时制度、地区法定假；跨时区与排班制不能套标准双休
-   **发薪**：考勤截止 → 核算 → 复核 → 过账 → 银行代发。任一步失败都要停在可重跑状态
-   **离职**：最后工作日、权限关闭、资产交还、竞业与证明开具。关闭权限晚于最后工作日是事故
-   **组织变更**：合并部门、切换汇报线要保留生效日；报表按生效日切片，不按查询当日回写历史

国内常见产品包括北森、PeopleSoft 本地实施、用友与金蝶 HCM；海外常见产品包括 Workday、SAP SuccessFactors。字段和国家/地区发薪方案以官方文档和客户法务配置为准。

### 数据与同意

员工数据属于高敏感个人信息：身份证、银行账号、健康信息、考核记录。处理依据、最小必要和保存期限要写进方案，法律文本以《个人信息保护法》和劳动合同制度为准。

跨系统同步只传完成开通或发薪所需字段。绩效评语默认不进客户支持工单，也不进对外 CRM。

### AI 产品切入点

-   职位描述草稿、简历要素抽取、面试纪要结构化；录用决策由用人经理与 HR 做出
-   入职材料完整性检查、合同到期提醒
-   假勤异常解释（余额不足、日历冲突）
-   薪酬核算差异说明，补发与扣款仍走发薪责任人
-   禁止自动发送录用或解除通知、禁止自动改薪、禁止根据聊天处分员工、禁止把候选人数据用于无关模型训练

### 常见误判

-   用协作账号清单代替员工主数据
-   离职只关 SSO、不关业务系统的本地账号
-   把考勤打卡异常直接判旷工
-   一套假勤规则覆盖所有国家或地区
-   让招聘机器人对候选人做出具有法律效果的承诺
